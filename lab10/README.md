## Задание

**Задание 9, вариант 9. Книги.**

Интерфейсы:

1. `Readable` — `read()`, `getPages()`, `default getReadingTimeMinutes()`,
   `static formatPages(int pages)`;
2. `Lendable` — `lend()`, `returnBook()`, `isAvailable()`.

Классы:

1. `Novel` — поля `title`, `author`, `pages`, `available`;
2. `Textbook` — поля `title`, `author`, `pages`, `subject`.

Оба класса реализуют `Readable` и `Lendable`. Требуется создать 3 романа и
2 учебника, прочитать их и продемонстрировать выдачу/возврат. Дополнительно
откомпилирован пример из теории — класс `Shape`, реализующий три интерфейса
`Drawable`, `Moveable`, `Resizable` (пункт меню 3).

| `Lendable.java` | интерфейс выдачи книги: `lend()`, `returnBook()`, `isAvailable()` |

| `Main.java` | интерактивное меню и сценарии заданий |

Логика выдачи: `lend()` возвращает `true` и переводит книгу в состояние
«выдана» только если она доступна; повторная выдача возвращает `false`.
`returnBook()` возвращает `true` только для выданной книги; повторный возврат
даёт `false`.

## Теория для защиты

### Контрольные вопросы (из задания)

1. **Что такое интерфейс и чем он отличается от класса.**
   Интерфейс — контракт поведения: набор абстрактных (и `default`/`static`)
   методов без состояния объекта. Класс — полноценная сущность с полями,
   конструкторами и реализацией. Интерфейс нельзя создать через `new`.

2. **Какие методы может содержать интерфейс.**
   Абстрактные (неявно `public abstract`), `default` с реализацией, `static`
   и `private` вспомогательные методы, а также константы. Поля экземпляра
   запрещены.

3. **Как класс реализует несколько интерфейсов.**
   Через `implements A, B, C` — класс обязан реализовать все абстрактные методы
   всех интерфейсов; иначе он объявляется `abstract`.

4. **Зачем нужны default- и static-методы интерфейса.**
   `default` позволяет добавить готовое поведение, не ломая существующие
   реализации; его можно переопределить. `static` — утилитарный метод,
   привязанный к интерфейсу и вызываемый через его имя.

5. **Что такое полиморфизм через интерфейс.**
   Ссылка интерфейсного типа может указывать на объект любого реализующего
   класса; вызов метода выполняется по фактической реализации (динамическое
   связывание). Пример — цикл по `List<Readable>`.

### Что рассказать о своей работе

1. `Readable` содержит абстрактные `read()`, `getPages()`, `default`
   `getReadingTimeMinutes()` (2 минуты на страницу) и `static`
   `formatPages()` — показать оба вида методов.
2. `Lendable` задаёт протокол выдачи: `lend()`, `returnBook()`, `isAvailable()`.
3. `Novel` и `Textbook` реализуют **два** интерфейса одновременно; это
   демонстрирует множественную реализацию.
4. Состояние `available` меняется только при корректных операциях: повторная
   выдача и повторный возврат возвращают `false`.
5. В пункте 1 меню одни и те же книги лежат в `List<Readable>` и обрабатываются
   полиморфно; в пункте 2 — в `List<Lendable>`.
6. `Shape` реализует сразу `Drawable`, `Moveable`, `Resizable`; `move()` и
   `resize()` меняют координаты и размер, `draw()` выводит состояние.
