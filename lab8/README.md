## Задание

**Задание 9, вариант 9. Компьютеры.**

Базовый класс `Computer`:

- поля: `processor` (процессор), `ram` (ОЗУ), `storage` (накопитель);
- методы: `getPerformance()` (производительность), `displayInfo()`.

Производные классы:

- `GamingPC` — добавляет поле `videoCard` (видеокарта),
  `getPerformance()` → `"Высокая производительность"`, уникальный метод
  `playGame()`;
- `OfficePC` — добавляет поле `monitorSize` (размер монитора),
  `getPerformance()` → `"Средняя производительность"`, уникальный метод
  `printDocument()`.

Требуется создать массив из 5 компьютеров (3 игровых и 2 офисных),
продемонстрировать полиморфный вывод и уникальные методы наследников.
Дополнительно откомпилирован пример из теории — цепочка классов
`Point1D` → `Point2D` → `Point3D`.

## Реализация

| Класс | Назначение |
|---|---|
| `Computer` | базовый класс: процессор, ОЗУ, накопитель; `getPerformance()`, `displayInfo()` |
| `GamingPC` | наследник: видеокарта; переопределяет `getPerformance()` и `displayInfo()`, метод `playGame()` |
| `OfficePC` | наследник: размер монитора; переопределяет `getPerformance()` и `displayInfo()`, метод `printDocument()` |
| `Point1D`, `Point2D`, `Point3D` | пример наследования из теории: конструкторы через `super()` и `this()` |
| `Main` | интерактивное меню: задание, пример из теории, выход |

Ключевые решения:

1. Поля всех классов закрытые (`private`), доступ — через геттеры и сеттеры.
2. Конструкторы наследников первой строкой вызывают `super(...)`, поэтому
   общая часть объекта инициализируется базовым классом.
3. `displayInfo()` наследников вызывает `super.displayInfo()` и дописывает
   своё уникальное поле — не дублирует общий код.
4. В `Main` массив объявлен как `Computer[]`, а объекты — наследники:
   вызовы `displayInfo()` и `getPerformance()` полиморфны.
5. Для уникальных методов используется `instanceof` с сопоставлением с
   образцом: `if (computer instanceof GamingPC gaming)`.
6. `Point3D()` по умолчанию вызывает `this(-1, -1, -1)`.

## Теория для защиты

### Контрольные вопросы

1. **Что такое наследование и для чего оно применяется.**
   Механизм получения новым классом полей и методов существующего класса.
   Объявляется через `extends`. Применяется для повторного использования
   кода и построения иерархий «является»: `GamingPC` является `Computer`.
   В Java возможно только одиночное наследование классов.

2. **Как вызвать конструктор суперкласса и зачем нужен `super`.**
   `super(аргументы)` — первой строкой конструктора наследника. Нужен для
   инициализации полей, объявленных в суперклассе, ведь они `private` и
   недоступны напрямую. Если конструктор суперкласса с параметрами не
   вызван, программа не скомпилируется.

3. **Переопределение и перегрузка.**
   Переопределение (`@Override`) — метод наследника с той же сигнатурой
   заменяет реализацию родителя. Перегрузка — несколько методов с одним
   именем и разными параметрами, обычно в одном классе. Переопределение
   обеспечивает полиморфизм, перегрузка — удобство вызова.

4. **Как работает полиморфизм.**
   Ссылке базового типа можно присвоить объект наследника. При вызове
   переопределённого метода компилятор проверяет только наличие метода в
   базовом типе, а JVM выбирает реализацию по фактическому классу объекта
   (динамическое связывание). Поэтому `Computer[]` с разными наследниками
   печатает разные значения `getPerformance()`.

5. **`instanceof` и приведение типов.**
   `instanceof` проверяет фактический тип объекта и возвращает `boolean`.
   Приведение `(GamingPC) computer` нужно, чтобы вызвать метод, которого нет
   в базовом классе. Без проверки неверное приведение даёт
   `ClassCastException`. В Java 16+ доступна запись
   `instanceof GamingPC gaming` с автоматическим созданием переменной.

### Что рассказать о своей работе

1. `Computer` хранит общие характеристики; наследники добавляют
   `videoCard` и `monitorSize`.
2. Конструкторы наследников вызывают `super(processor, ram, storage)` —
   общая часть инициализируется один раз.
3. `getPerformance()` переопределён в обоих наследниках; массив `Computer[]`
   демонстрирует полиморфизм.
4. `displayInfo()` наследников расширяет `super.displayInfo()`, а не
   копирует его.
5. `playGame()` и `printDocument()` вызываются после `instanceof` и
   приведения — показать на пункте 1 меню.
6. Цепочка `Point1D` → `Point2D` → `Point3D`: `super(x)`, `super(x, y)`,
   `this(-1, -1, -1)`; `toString()` показывает все координаты.
7. Показать `mvn test` (10 тестов) и оба пункта меню.
