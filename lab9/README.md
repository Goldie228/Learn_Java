## Задание

**Задание 9, вариант 9. Транспорт.**

Абстрактный класс `Transport`:

- поля: `capacity` (вместимость), `speed` (скорость), `fuel` (топливо);
- абстрактные методы: `deliver()` (доставить груз),
  `calculateTime()` (рассчитать время);
- конкретный метод: `displayInfo()`.

Конкретные классы:

- `Truck` — добавляет поле `cargoWeight` (вес груза),
  `deliver()` → `"Доставляет груз по суше"`, `calculateTime()` =
  расстояние / скорость;
- `Ship` — добавляет поле `tonnage` (тоннаж),
  `deliver()` → `"Доставляет груз по воде"`, `calculateTime()` =
  расстояние / (скорость * 0.8).

Требуется создать массив из 5 транспортных средств (3 грузовика и
2 корабля), вывести информацию, способ доставки и время доставки.
Дополнительно откомпилирован пример из теории — `Animal` / `Dog`
с демонстрацией порядка вызова конструкторов.

## Реализация

| Класс | Назначение |
|---|---|
| `Transport` | абстрактный базовый класс: вместимость, скорость, топливо; абстрактные `deliver()` и `calculateTime()`, конкретный `displayInfo()` |
| `Truck` | грузовик: вес груза, доставка по суше, время = расстояние / скорость |
| `Ship` | корабль: тоннаж, доставка по воде, время = расстояние / (скорость * 0.8) |
| `Animal`, `Dog` | пример из теории: абстрактный класс и конкретный наследник |
| `Main` | интерактивное меню: задание, пример из теории, пояснение про abstract, выход |

Ключевые решения:

1. `Transport` объявлен `abstract`, содержит два абстрактных метода и один
   конкретный — общий `displayInfo()`.
2. Поля закрытые; доступ через геттеры и сеттеры. Скорость проверяется и в
   конструкторе, и в сеттере.
3. Расстояние проверяется в `calculateTime()` обоих наследников через
   общий защищённый метод `checkDistance(double)`.
4. При `distance < 0` выбрасывается `IllegalArgumentException`; при
   `speed <= 0` — тоже `IllegalArgumentException`.
5. `displayInfo()` наследников вызывает `super.displayInfo()` и добавляет
   своё поле.
6. В `Main` массив объявлен как `Transport[]`, объекты — `Truck` и `Ship`;
   вызовы `deliver()` и `calculateTime()` полиморфны.
7. Уникальные поля наследников выводятся после `instanceof` и приведения.
8. В пункте 3 меню показана закомментированная строка
   `new Transport(...)` с пометкой, что она не компилируется.

## Теория для защиты

### Контрольные вопросы

1. **Что такое абстрактный класс.**
   Класс, объявленный с `abstract`, который описывает общий контракт и
   может содержать как конкретные, так и абстрактные методы. Служит базой
   для наследников и выражает общее понятие, для которого нет полноценной
   реализации (`Transport`).

2. **Можно ли создать объект абстрактного класса.**
   Нет: `new Transport(...)` не компилируется
   (`Transport is abstract; cannot be instantiated`). Но можно объявить
   ссылку `Transport t` и присвоить ей объект наследника.

3. **Что такое абстрактный метод.**
   Метод без тела, объявленный с `abstract` и заканчивающийся `;`.
   Он сообщает, что реализация обязана быть в наследнике. Может находиться
   только в абстрактном классе или интерфейсе; не бывает `private`,
   `static`, `final`.

4. **Может ли абстрактный класс иметь конструктор.**
   Да. Он вызывается через `super(...)` из конструктора наследника и
   инициализирует общие поля. Непосредственно создать объект такого класса
   всё равно нельзя.

5. **Может ли абстрактный класс не иметь абстрактных методов.**
   Да, но тогда он только запрещает создание собственных объектов и
   используется как вершина иерархии.

6. **Какой класс должен реализовать все абстрактные методы.**
   Конкретный (неабстрактный) класс-наследник. Если реализованы не все
   методы, наследник тоже объявляется `abstract`.

7. **Можно ли объявить абстрактный метод как `private`.**
   Нет: закрытый метод нельзя переопределить, а абстрактный метод
   существует именно для переопределения. Также недопустимы `static`,
   `final`, `native`, `synchronized`.

### Что рассказать о своей работе

1. `Transport` задаёт общий контракт: `deliver()` и `calculateTime()` —
   абстрактные, `displayInfo()` — готовый общий метод.
2. `super(capacity, speed, fuel)` в конструкторах `Truck` и `Ship`
   инициализирует поля базового класса; сами наследники добавляют
   `cargoWeight` и `tonnage`.
3. Формулы разные: грузовик `distance / speed`, корабль
   `distance / (speed * 0.8)`; при 500 км и 80 км/ч это 6,25 и 7,8125 ч.
4. Валидация: `speed <= 0` — в конструкторе и сеттере, `distance < 0` — в
   `calculateTime()`; выбрасывается `IllegalArgumentException`.
5. Массив `Transport[]` заполнен `Truck` и `Ship`; один цикл вызывает
   разные реализации — полиморфизм.
6. `Animal` / `Dog`: абстрактный класс с конструктором; `Animal` печатает
   сообщение первым, потому что `super(...)` выполняется до тела
   конструктора наследника.
7. Пункт 3 меню объясняет запрет `new Transport(...)`; в коде строка
   закомментирована с пометкой об ошибке.
8. Показать `mvn test` (12 тестов) и пункты меню 1–3.
