## Задание

**Задание 9, вариант 9.** Сущность «Пользователь» (`User`):

- поля: `username`, `email`, `password`, `age`;
- конструктор с проверкой: формат email, пароль не короче 6 символов;
- собственные исключения:
  - `InvalidUserDataException` — неверные данные;
  - `UserNotFoundException` — пользователь не найден;
  - `AuthenticationException` — ошибка аутентификации;
- методы: `authenticate(String password)`, `updateEmail(String newEmail)`.

Требуется создать систему пользователей и выполнить операции регистрации
и входа.

---

## Реализация

### Классы предметной области

| Класс | Назначение |
|---|---|
| `InvalidUserDataException` | checked-исключение с полем `field` — какое поле не прошло проверку |
| `UserNotFoundException` | checked-исключение с полем `username`, сообщение «Пользователь … не найден» |
| `AuthenticationException` | checked-исключение с полями `username` и `attempts` (номер неудачной попытки) |
| `User` | данные пользователя, валидация, аутентификация, обновление email |
| `UserService` | `LinkedHashMap` пользователей: регистрация, поиск, вход, обновление email |
| `Main` | интерактивное меню и демонстрационные сценарии |

### Проверки в `User`

- `username` — не `null` и не пустая/пробельная строка;
- `email` — соответствует `^[\w.%+-]+@[\w.-]+\.[A-Za-z]{2,}$`;
- `password` — не короче 6 символов (геттера пароля нет);
- `age` — от 0 до 150.

При неверном пароле `authenticate()` увеличивает счётчик неудачных попыток
и выбрасывает `AuthenticationException`; после успешного входа счётчик
сбрасывается. `setEmail()` (и делегирующий `updateEmail()`) повторно
проверяет формат адреса.

### Пункты меню

1. Регистрация: два корректных пользователя (`ivan`, `olga`) и два
   некорректных (плохой email, короткий пароль); каждый вызов обёрнут в
   `try-catch-finally`, в `finally` выводится «Операция регистрации завершена».
2. Вход: успешный вход, неверный пароль, неизвестный пользователь — три
   отдельных блока `try-catch`.
3. Обновление email: корректный и некорректный адрес.
4. Пример из теории: multi-catch `NumberFormatException | ArithmeticException`,
   `finally`, try-with-resources для записи и чтения `data/theory.txt`.
5. Вывод списка зарегистрированных пользователей.

## Теория для защиты

### Контрольные вопросы

1. **Что такое исключение?** Событие, нарушающее нормальный ход программы;
   в Java — объект-наследник `Throwable`, создаваемый при ошибке.
2. **Иерархия.** `Throwable` → `Error` и `Exception`; `Exception` →
   `RuntimeException` и проверяемые исключения (`IOException` и др.).
3. **Checked и unchecked.** Checked проверяются компилятором (нужно
   обработать или объявить `throws`); unchecked — наследники
   `RuntimeException`, проверка не требуется.
4. **Ключевые слова:** `try`, `catch`, `finally`, `throw`, `throws`.
5. **try-catch-finally.** В `try` — опасный код, в `catch` — обработка,
   `finally` выполняется всегда.
6. **throw и throws.** `throw` создаёт исключение, `throws` объявляет
   возможные исключения в сигнатуре метода.
7. **finally** выполняется при любом завершении `try`, в том числе при
   `return` и при повторном выбрасывании исключения.
8. **Своё исключение** — класс, наследующий `Exception` (checked) или
   `RuntimeException` (unchecked), с конструктором, вызывающим `super`.
9. **try-with-resources** автоматически вызывает `close()` у ресурсов,
   реализующих `AutoCloseable`.
10. **Несколько типов** обрабатываются несколькими `catch` или multi-catch.
11. **Multi-catch** (`A | B e`) объединяет обработку разных типов.
12. **Деление на ноль** для целых чисел даёт `ArithmeticException`.
13. **Необработанное исключение** завершает поток и печатает stack trace.
14. **Сообщение** — `e.getMessage()`, тип — `e.getClass().getSimpleName()`.
15. **Stack trace** — последовательность вызовов до места ошибки.
16. **Несколько ресурсов** перечисляются в `try (...)` через `;`.

### Что рассказать о своей работе

1. Три собственных checked-исключения хранят контекст: поле (`field`), имя
   пользователя (`username`), номер неудачной попытки (`attempts`).
2. Валидация вынесена в конструктор `User` и в `setEmail()` — повторное
   использование одной и той же проверки email; `updateEmail()` делегирует
   сеттеру.
3. `authenticate()` использует `throw new AuthenticationException(...)`,
   а методы `UserService` объявляют `throws` — видно разницу между `throw`
   и `throws`.
4. Пароль не выдаётся геттером: снаружи доступна только проверка
   `checkPassword()`.
5. Пункт 4 показывает multi-catch, обязательный `finally` и
   try-with-resources при записи и чтении `data/theory.txt`.
6. `mvn test` — 21 тест, включая отрицательные сценарии (неверный email,
   короткий пароль, дубликат, неизвестный пользователь, неверный пароль).
