## Задание

**Задание 9, вариант 9. Компьютеры.**

Базовый класс `Computer`:

- поля `model`, `ram`, `storage`;
- перегруженные методы:
  - `run()` → `"Компьютер работает"`;
  - `run(String program)` → `"Запускает " + program`;
  - `run(int processes)` → `"Запускает " + processes + " процессов"`;
- метод для переопределения `getPerformance()` → `"Средняя"`.

Производные классы:

1. `GamingPC` — переопределяет `getPerformance()` → `"Высокая"`;
2. `OfficePC` — переопределяет `getPerformance()` → `"Средняя"`.

Требуется создать компьютеры и продемонстрировать перегрузку и
переопределение методов, а также `instanceof` и нисходящее приведение.

## Реализация

| Файл | Назначение |
|---|---|
| `Computer.java` | базовый класс: поля, геттеры/сеттеры, три версии `run()`, `getPerformance()`, `displayInfo()` |
| `GamingPC.java` | наследник с видеокартой `videoCard`, производительностью `"Высокая"` и своим `run(String game, int fps)` |
| `OfficePC.java` | наследник с размером монитора `monitorSize`, производительностью `"Средняя"` и своим `run(String program, boolean minimized)` |
| `Main.java` | интерактивное меню и сценарии заданий |

`getPerformance()` в `displayInfo()` вызывается через `this`, поэтому для
объекта наследника выводится переопределённое значение. Собственные
перегруженные методы наследников вызываются после проверки `instanceof`
и нисходящего приведения.

## Теория для защиты

### Контрольные вопросы (из задания)

1. **Что такое полиморфизм.**
   Способность одного имени или ссылки работать с объектами разных типов.
   В Java различают статический полиморфизм (перегрузка, выбор на этапе
   компиляции) и динамический (переопределение, выбор во время выполнения).

2. **Чем перегрузка методов отличается от переопределения.**
   Перегрузка — несколько методов с одним именем и разными параметрами в одном
   классе или иерархии. Переопределение — метод наследника с той же
   сигнатурой, что и у базового класса, меняющий реализацию.

3. **Как выбирается перегруженный метод.**
   Компилятором по количеству и статическим типам фактических аргументов;
   возвращаемый тип в выборе не участвует.

4. **Как работает динамическое связывание при переопределении.**
   Ссылка базового типа хранит объект наследника; JVM при вызове выбирает
   реализацию по фактическому типу объекта. Поэтому `Computer pc = new
   GamingPC(...)` даёт `"Высокая"` при вызове `pc.getPerformance()`.

5. **Зачем нужен оператор instanceof.**
   Для проверки фактического типа перед нисходящим приведением, чтобы избежать
   `ClassCastException`. В Java 21 pattern-форма сразу создаёт переменную
   нужного типа: `if (pc instanceof GamingPC gaming) { ... }`.

### Что рассказать о своей работе

1. `Computer` демонстрирует **перегрузку** `run()` тремя версиями: без
   параметров, со строкой и с целым числом.
2. `GamingPC` и `OfficePC` **переопределяют** `getPerformance()`; вызов через
   ссылку `Computer` возвращает значение наследника — динамический полиморфизм.
3. `displayInfo()` базового класса вызывает `getPerformance()` полиморфно,
   а наследники дополняют вывод своим полем (`videoCard` / `monitorSize`).
4. Собственные перегрузки наследников: `GamingPC.run(String, int)` и
   `OfficePC.run(String, boolean)` — их можно вызвать только после приведения.
5. В пункте 3 меню `instanceof` отделяет игровые и офисные компьютеры,
   после чего выполняется безопасное нисходящее приведение.
6. Показать `mvn test` (8 тестов) и все три пункта меню.
