## Задание

**Задание 1. Инструменты (Generics + Map).** Базовый класс `Tool` с полями
`name`, `id`, `weight`, конструктором, геттерами и `displayInfo()`.
Наследники: `Hammer` (`handleLength`), `Screwdriver` (`tipType`), `Wrench`
(`size`) с переопределённым `displayInfo()`. Создать
`Map<String, Tool>` с названием инструмента в качестве ключа, добавить
3 молотка, 3 отвёртки и 2 ключа, вывести все ключи и значения, размер Map,
статистику по типам и продемонстрировать перезапись значения повторным ключом.

**Задание 2, вариант 9. Отели (List, сортировка, компаратор).** Класс `Hotel`
с полями `id`, `name`, `city`, `stars`, `guestRatings` (`List<Integer>`),
средним рейтингом, валидацией звёзд и оценок. Сервис `HotelService`:

1. вывести отели со средним рейтингом < 3;
2. повысить звёздность отелей со средним рейтингом >= 4 (не выше 5);
3. `printHotels(List<Hotel>, int stars)` — отели с заданным числом звёзд;
4. отсортировать по убыванию среднего рейтинга, при равенстве — по названию
   в алфавитном порядке, вывести ID, название и средний рейтинг.

## Реализация

| Класс | Назначение |
|---|---|
| `Tool`, `Hammer`, `Screwdriver`, `Wrench` | иерархия инструментов, общие поля в базовом классе |
| `Hotel` | отель: защитная копия списка оценок, `getAverageRating()`, `setStars()`, `addRating()` |
| `HotelService` | `lowRated`, `raiseStarsForBest`, `byStars`, `sortedByRating`, `printHotels` |
| `Box<T>`, `Pair<K,V>` | обобщённые классы из теоретической части |
| `Main` | интерактивное меню, данные и демонстрационные сценарии |

Ключевые решения:

- `Hotel` копирует переданный список оценок в конструкторе и отдаёт его
  только для чтения, поэтому внешний код не может изменить состояние отеля;
- `getAverageRating()` возвращает `0.0` для пустого списка и не делит на ноль;
- `setStars()` и `addRating()` проверяют диапазон `1..5` и выбрасывают
  `IllegalArgumentException`;
- `raiseStarsForBest()` использует `Math.min(5, stars + 1)` — выше пяти звёзд
  подняться нельзя;
- `sortedByRating()` не меняет исходный список: сортируется копия, компаратор
  собран как `comparingDouble(...).reversed().thenComparing(..., CASE_INSENSITIVE_ORDER)`;
- в меню каждый пункт заново создаёт набор данных, поэтому результаты не
  зависят от порядка выбора пунктов.

## Теория для защиты

### Контрольные вопросы (из задания)

1. **Основные интерфейсы коллекций.** `Collection`, `List`, `Set`, `Queue`,
   `Deque`, `Map`. `Map` не наследует `Collection`, потому что хранит пары
   «ключ — значение».
2. **Разница между `List` и `Set`.** `List` упорядочен, допускает дубликаты и
   доступ по индексу; `Set` хранит только уникальные элементы, порядок зависит
   от реализации.
3. **Разница между `ArrayList` и `LinkedList`.** `ArrayList` — динамический
   массив: доступ по индексу O(1), вставка в середину O(n). `LinkedList` —
   двусвязный список: вставка/удаление O(1) при известной позиции, доступ по
   индексу O(n).
4. **Разница между `HashSet` и `TreeSet`.** `HashSet` быстрее (O(1) в среднем),
   порядок не определён; `TreeSet` хранит элементы отсортированными, операции
   O(log n).
5. **Разница между `HashMap` и `TreeMap`.** `HashMap` даёт доступ O(1) и не
   гарантирует порядок; `TreeMap` хранит ключи отсортированными, доступ
   O(log n).
6. **Как перебрать элементы коллекции.** `for-each`, `Iterator`, `forEach()`;
   для `Map` — `entrySet()`, `keySet()`, `values()`.
7. **Что такое `Iterator`.** Объект последовательного обхода коллекции с
   методами `hasNext()`, `next()`, `remove()`; позволяет удалять элементы во
   время обхода.
8. **Как отсортировать коллекцию.** `Collections.sort(list)` — естественный
   порядок, `list.sort(comparator)` — свой `Comparator`; для `Map` —
   `TreeMap` с нужным компаратором.

### Что рассказать о своей работе

1. `Tool` — базовый класс, `Hammer`/`Screwdriver`/`Wrench` добавляют свои поля
   и переопределяют `displayInfo()`, поэтому `Map<String, Tool>` хранит разные
   типы в одном контейнере.
2. Ключ Map — название инструмента; `put` с существующим ключом не увеличивает
   размер, а заменяет значение (показано в демо-блоке: было `Wrench`, стало
   `Screwdriver`, размер остался `1`).
3. `Hotel.getAverageRating()` считает среднее по `List<Integer>` и возвращает
   `0.0` при пустом списке; конструктор копирует список, чтобы внешние
   изменения не влияли на отель.
4. `HotelService` отделён от `Hotel`, поэтому все операции покрываются тестами
   без запуска меню.
5. `sortedByRating()` сортирует копию списка компаратором
   `comparingDouble(...).reversed().thenComparing(name, CASE_INSENSITIVE_ORDER)`
   — сначала по убыванию рейтинга, затем по алфавиту без учёта регистра.
6. В наборе данных есть все ветки: рейтинг ниже `3` («Припять», «Юбилейный»),
   ровно `3.0` («Турист»), `>= 4` (пять отелей), ничья `4.5` («Астория» и
   «Бригантина») и пустой список отзывов («Юбилейный»).
7. `Box<T>` и `Pair<K,V>` показывают параметризацию типов: приведение типов не
   требуется, а неверный тип обнаруживается на этапе компиляции.
