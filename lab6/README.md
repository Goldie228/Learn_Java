## Задание

**Задание 1, вариант 3.** Класс «Билет» (`Ticket`): поля `event`,
`seatNumber`, `price`; конструктор; геттеры; метод `applyDiscount()`.
В `main` создать билет и применить скидку.

Все поля класса `Ticket` объявлены `private` (инкапсуляция): читать их можно
только через геттеры, а цена меняется исключительно изнутри класса — методом
`applyDiscount()`. Помимо задания, в меню добавлены примеры из теории
(`MyClass`, `DayWeek`).

## Теория для защиты

### Контрольные вопросы (из задания)

1. **Что такое инкапсуляция?**
   Принцип ООП: данные и методы их обработки объединены в классе, а доступ
   к внутреннему состоянию ограничен (поля `private` + геттеры/сеттеры).
   Защищает данные от некорректного использования и скрывает реализацию.

2. **Что такое иерархия классов?**
   Структура классов, связанных наследованием («родитель — потомок»).
   Корень — `Object`; потомок расширяет родителя.

3. **Как наследуются поля и методы классов?**
   `public`/`protected` — наследуются и доступны; `private` — наследуются,
   но напрямую недоступны (только через методы родителя); `default` — только
   в пределах одного пакета. Конструкторы не наследуются.

4. **Модификаторы доступа (Access modifiers).**
   `public`, `default` (без слова), `protected`, `private` — определяют,
   откуда виден элемент класса.

5. **Геттеры и сеттеры (Getters and Setters).**
   Методы чтения (`getX`) и записи (`setX`) поля. Обеспечивают контролируемый
   доступ и позволяют добавить проверки.

6. **public.** Виден всем классам и пакетам.

7. **default.** Модификатор по умолчанию (не указывается явно); виден только
   в пределах своего пакета.

8. **protected.** Как `default`, но доступен ещё и классам-наследникам
   (в том числе из других пакетов).

9. **private.** Виден только самому классу; снаружи доступ невозможен.

### Что рассказать о своей работе

1. `Ticket` демонстрирует инкапсуляцию: поля `private`, чтение через
   `getEvent()/getSeatNumber()/getPrice()`, изменение цены — только через
   `applyDiscount()`.
2. В конструкторе и приватном `setPrice()` есть проверка (цена не может быть
   отрицательной) — пример контроля над состоянием.
3. `applyDiscount()` перегружен: без аргумента — скидка 10 %, с аргументом —
   заданный процент; некорректная скидка игнорируется.
4. Пример `MyClass` показывает геттер/сеттер для скрытого поля.
5. Пример `DayWeek` показывает проверку значения (1..7) в сеттере.
6. Продемонстрировать работу меню, тесты и попытку обратиться к `ticket.price`
   (ошибка компиляции).
