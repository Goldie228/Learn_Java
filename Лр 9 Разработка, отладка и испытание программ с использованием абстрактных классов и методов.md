ТЕОРЕТИЧЕСКИЕ СВЕДЕНИЯ ДЛЯ ВЫПОЛНЕНИЯ РАБОТЫ 

Множество моделей предметов реального мира обладают некоторым  набором общих характеристик и правил поведения. Абстрактное понятие  «Геометрическая фигура» может содержать описание геометрических  параметров и расположения центра тяжести в системе координат, а также  возможности определения площади и периметра фигуры. Однако в общем  случае дать конкретную реализацию приведенных характеристик и  функциональности невозможно ввиду слишком общего их определения. Для  конкретного понятия, например, «Квадрат», дать описание линейных  размеров и определения площади и периметра не составляет труда. 

Абстрагирование понятия должно предоставлять абстрактные  характеристики предмета реального мира, а не его ожидаемую реализацию.  Грамотное выделение абстракций позволяет структурировать код  программной системы в целом и повторно использовать абстрактные понятия  для конкретных реализаций при определении новых возможностей  абстрактной сущности. 

Абстрактные классы объявляются с ключевым словом abstract и  содержат объявления абстрактных методов, которые не реализованы в этих  классах, а будут реализованы в подклассах. Абстрактный класс может и не  содержать вовсе абстрактных методов. Предназначение такого класса – быть  вершиной иерархии его различных реализаций.  
2 

Объекты таких классов нельзя создать с помощью оператора new, но  можно создать объекты подклассов, которые реализуют все эти методы. При  этом допустимо объявлять ссылку на абстрактный класс, но инициализировать  ее можно только объектом производного от него класса. Абстрактные классы  могут содержать и полностью реализованные методы, а также конструкторы и  поля данных. 

С помощью абстрактного класса объявляется контракт (требования к  функциональности) для его подклассов. Примером может служить уже  рассмотренный выше абстрактный класс Number и его подклассы Byte, Float и  другие. 

Класс Number объявляет контракт на реализацию ряда методов по  преобразованию данных к значению конкретного базового типа, например,  floatValue(). 

Можно предположить, что реализация метода будет различной для  каждого из классов­оболочек. Объект класса Number нельзя создать явно при  помощи его собственного конструктора. 

Абстракция – это принцип ООП, при котором выделяются только  существенные характеристики объекта, игнорируя несущественные детали. В Java абстракция реализуется через: 

\- Абстрактные классы (“abstract class”)   
\- Интерфейсы (“interface”) 

Абстрактный класс – это класс, который служит базой для других  классов и может содержать как полностью реализованные методы, так и  абстрактные методы без реализации. 

Синтаксис 

public abstract class ИмяКласса {   
 // Поля (обычные) 

 private int field; 


 // Конструктор (вызывается из наследников) 

 public ИмяКласса(int field) { 

 this.field \= field;   
 } 


 // Конкретный метод (с реализацией) 

 public void concreteMethod() { 

 System.out.println("Это обычный метод"); 

 } 


 // Абстрактный метод (без реализации) 

 public abstract void abstractMethod(); 

} 

Ключевое слово – объявляется с модификатором “abstract” 

**Нельзя создать объект** (new AbstractClass() – ошибка)   
3 

Наследование – служит для наследования (используется “extends”) \| Содержимое – может содержать поля, конструкторы, конкретные и  абстрактные методы  

Конструктор – может иметь конструктор (вызывается через “super()” в  наследниках)  

Наследники – если наследник не реализует все абстрактные методы, он  тоже должен быть абстрактным  

Модификаторы – Может иметь любые модификаторы доступа  Абстрактный метод – это метод, объявленный без реализации (без тела).  Он определяет сигнатуру (имя, параметры, возвращаемый тип), но не  определяет поведение. 

Синтаксис 

public abstract returnType methodName(parameters); 

Важно: После сигнатуры метода ставится точка с запятой (“;”), а не  фигурные скобки “{}”. 

Характеристики абстрактного метода: 

Ключевое слово – объявляется с модификатором “abstract” 

Реализация – не имеет тела (реализации)  

Наследование – должен быть реализован (переопределен) в первом  конкретном классе-наследнике    
Может быть объявлен ТОЛЬКО в абстрактном классе или интерфейсе  Модификаторы – не может быть “private”, “static”, “final”, “native”,  “synchronized” \| 

Правила для абстрактного класса: 

1\. Класс должен быть объявлен как “abstract”, если он содержит хотя бы  один абстрактный метод.   
2\. Абстрактный класс может не содержать абстрактных методов (но  тогда бессмысленно объявлять его абстрактным). 

3\. Абстрактный класс не может быть “final” (т.к. его цель – наследование). 

4\. Абстрактный класс может иметь конструктор (используется для  инициализации полей при создании объектов наследников). 5\. Абстрактный класс может реализовывать интерфейсы. 

Правила для абстрактного метода: 

1\. Абстрактный метод не имеет тела (заканчивается точкой с запятой). 2\. Абстрактный метод может быть объявлен только в абстрактном классе  или интерфейсе. 

3\. Абстрактный метод не может быть “private” (т.к. его должны  переопределять наследники). 

4\. Абстрактный метод не может быть “static” (т.к. статические методы  не переопределяются). 

5\. Абстрактный метод не может быть “final” (т.к. финальные методы  нельзя переопределять).  
4 

Правила для наследников абстрактного класса: 

1\. Конкретный класс-наследник ДОЛЖЕН реализовать ВСЕ  абстрактные методы родителя. 

2\. Если наследник не реализует все абстрактные методы, он должен быть  объявлен как “abstract”. 

3\. Наследник может переопределять конкретные методы родителя (как  и в обычном наследовании). 

4\. Наследник может добавлять свои поля и методы.   
Абстрактный класс может иметь конструктор, хотя объект этого класса  создать нельзя. Конструктор используется для: 

\- Инициализации полей абстрактного класса 

\- Выполнения подготовительных действий 

Конструктор абстрактного класса вызывается через “super()” в  конструкторе наследника.   
abstract class Animal { 

 private String name; 

 private int age; 


 // Конструктор абстрактного класса 

 public Animal(String name, int age) {   
 this.name \= name; 

 this.age \= age; 

 System.out.println("Конструктор Animal вызван"); 

 } 

 public abstract void makeSound(); 

}   
class Dog extends Animal { 

 private String breed; 

 // Конструктор наследника вызывает super() 

 public Dog(String name, int age, String breed) { 

 super(name, age); // Вызов конструктора Animal 

 this.breed \= breed;   
 System.out.println("Конструктор Dog вызван"); 

 } 


 @Override 

 public void makeSound() { 

 System.out.println("Гав-гав\!");   
 } 

} 

// В main: 

Dog dog \= new Dog("Шарик", 3, "Овчарка"); 

// Вывод:  
5 

// Конструктор Animal вызван 

// Конструктор Dog вызван   
Важные правила: 

1\. Если в абстрактном классе есть конструктор с параметрами,  наследник обязан вызвать его через “super()”. 

2\. Если в абстрактном классе нет конструктора, компилятор создает  конструктор по умолчанию. 

3\. Вызов “super()” должен быть первой строкой в конструкторе  наследника. 

Если у вас есть метод, который должен быть реализован во всех  наследниках, но по-разному – делайте его абстрактным.
