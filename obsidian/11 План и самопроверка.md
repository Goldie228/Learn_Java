## Алгоритм ответа у доски

1. **Уточни задание**: «Нужен базовый класс с тремя приватными полями и два наследника?»
2. **Назови каркас**: поля → конструктор → геттеры/сеттеры → методы.
3. **Напиши базовый класс**.
4. **Напиши наследников**: `super(...)`, новое поле, `@Override`.
5. **Покажи использование**: массив/список базового типа, цикл, `instanceof`.
6. **Проговори решение**: «Здесь полиморфизм, потому что…».

Если просят интерфейс — сразу скажи: «Методы `public abstract`, полей-состояния
нет, класс реализует через `implements`».

## Самопроверка: напиши по памяти

| № | Задание | Критерий «сдано» |
|---|---------|------------------|
| 1 | `Student`: 3 приватных поля, конструктор, геттеры/сеттеры | компилируется, поля закрыты |
| 2 | `Computer` → `GamingPC`, `OfficePC` | `super`, `@Override`, массив 3+2 |
| 3 | Абстрактный `Transport` → `Truck`, `Ship` | нельзя `new Transport`, формулы верны |
| 4 | `Readable`, `Lendable` → `Novel` | оба интерфейса, `lend`/`returnBook` |
| 5 | Перегрузка `run()` + переопределение | 3 версии, вызов через базовый тип |
| 6 | `Box<T>`, `Pair<K,V>`, `Map<String, Tool>` | без приведения типов |
| 7 | Сортировка отелей по рейтингу и названию | `Comparator`, `reversed`, `thenComparing` |
| 8 | Своё исключение + валидация | `throws`, `try-catch`, поле исключения |
| 9 | Запись/чтение чисел в файл | UTF-8, try-with-resources, `parseInt` |
| 10 | Git: ветка → merge | 5 команд без подсказки |

> [!warning] Если не получается с нуля
> Разрежь задачу: сначала только поля и конструктор, скомпилируй; потом
> методы; потом наследников. Не пиши весь файл сразу — так ошибки ищутся
> быстрее.

## Красные флаги: так говорить нельзя

| Неверно | Верно |
|---------|-------|
| «Интерфейс можно создать через `new`» | нельзя, нет конструктора |
| «Абстрактный класс нельзя наследовать» | можно и нужно, нельзя инстанцировать |
| «Переопределение — это разные параметры» | это перегрузка |
| «`static` можно переопределить» | скрытие, не переопределение |
| «В интерфейсе любые поля» | только `public static final` |
| «`finally` не выполнится при `return`» | выполнится |
| «`HashMap` сортирует» | нет, сортирует `TreeMap` |
| «`ArrayList` хранит уникальные» | нет, это `Set` |
| «`FileOutputStream` всегда дописывает» | по умолчанию перезаписывает |
| «GitHub — это Git» | GitHub — хостинг, Git — VCS |
| «`merge` всегда создаёт коммит» | только не fast-forward; в лабе `--no-ff` |
| «`super()` можно вызвать в любом месте» | только первой строкой конструктора |

## Мини-тест перед зеркалом

Ответь за 2 минуты:

1. Чем `implements` отличается от `extends`?
2. Почему нельзя `new Transport()`?
3. Что делает `super()` и где он стоит?
4. Чем перегрузка отличается от переопределения?
5. Что выведет `Animal a = new Dog(); a.sound();`?
6. Где хранятся уникальные элементы?
7. Чем `HashMap` отличается от `TreeMap`?
8. Что такое checked-исключение?
9. Зачем `try-with-resources`?
10. Что делает `git merge --no-ff`?

Если запнулся — вернись в соответствующую заметку, не перечитывай всё.
