# Полиморфизм (ЛР11)

> [!abstract] Одной фразой
> Полиморфизм — один и тот же вызов даёт разное поведение в зависимости
> от фактического типа объекта.

## Два вида

| Вид | Механизм | Когда решается | Пример |
|-----|----------|----------------|--------|
| Статический | перегрузка (overloading) | на этапе компиляции | `add(int,int)` / `add(double,double)` |
| Динамический | переопределение (overriding) | во время выполнения | `getPerformance()` у наследников |

```java
Computer c = new GamingPC(...);
c.getPerformance();   // "Высокая" — динамический полиморфизм
```

Компилятор видит тип ссылки `Computer`, а JVM вызывает метод фактического
класса `GamingPC`. Это позднее связывание (late binding).

## Перегрузка (overloading)

```java
public class Calculator {
    public int add(int a, int b) { return a + b; }
    public int add(int a, int b, int c) { return a + b + c; }
    public double add(double a, double b) { return a + b; }
    public double add(int a, double b) { return a + b; }
    public double add(double a, int b) { return a + b; }
}
```

Правила:

- имя метода одинаковое;
- параметры различаются **количеством, типом или порядком**;
- возвращаемый тип сам по себе перегрузку не создаёт;
- имена параметров сами по себе перегрузку не создают;
- модификаторы и `throws` сами по себе тоже не создают.

```java
int f(int a, int b);
// double f(int a, int b);   // ошибка: отличается только возвращаемый тип
// int f(int x, int y);      // ошибка: те же типы, другие имена
```

### Как компилятор выбирает версию

Порядок: точное совпадение → расширение примитивов (`int → long → double`) →
autoboxing (`int → Integer`) → varargs. Если подходят две версии одинаково
хорошо — ошибка неоднозначности.

```java
void f(int x) {}
void f(Integer x) {}
f(5);        // выберется f(int): точное совпадение
f(null);     // выберется f(Integer): int не может быть null
```

> [!warning] Ловушка с `null`
> Если есть `f(String)` и `f(Object)`, вызов `f(null)` выберет более
> специфичный `f(String)`.

## Переопределение (overriding)

```java
class Computer {
    public String getPerformance() { return "Средняя"; }
}

class GamingPC extends Computer {
    @Override
    public String getPerformance() { return "Высокая"; }
}
```

Правила:

- имя и параметры совпадают;
- возвращаемый тип тот же или подтип;
- доступ не сужается;
- исключения не расширяются;
- нельзя переопределить `private`, `final`, `static`;
- `@Override` рекомендуется.

### Перегрузка vs переопределение

| Вопрос | Перегрузка | Переопределение |
|--------|------------|-----------------|
| Где | в одном классе или в иерархии | в наследнике |
| Имя | одинаковое | одинаковое |
| Параметры | **разные** | **такие же** |
| Возврат | может быть любым | тот же/подтип |
| Связывание | раннее (compile-time) | позднее (runtime) |
| `@Override` | нет | да |
| Цель | удобство API | изменить поведение |

## Поля не полиморфны

```java
class A { int x = 1; int getX() { return x; } }
class B extends A { int x = 2; int getX() { return x; } }

A a = new B();
System.out.println(a.x);       // 1 — поле берётся по типу ссылки
System.out.println(a.getX());  // 2 — метод по фактическому типу
```

Поля не переопределяются, а **скрываются**. Поэтому к полям обращаются через
методы, а не напрямую.

## `instanceof` и приведение

```java
Computer[] computers = {
    new GamingPC(...), new OfficePC(...)
};

for (Computer c : computers) {
    System.out.println(c.getPerformance());   // полиморфно

    if (c instanceof GamingPC) {
        GamingPC g = (GamingPC) c;
        System.out.println(g.run("Cyberpunk", 120));
    } else if (c instanceof OfficePC) {
        OfficePC o = (OfficePC) c;
        System.out.println(o.run("Excel", true));
    }
}
```

- восходящее преобразование — неявное и безопасное;
- нисходящее — явное, только после `instanceof`;
- иначе `ClassCastException`.

## Код варианта 9 (ЛР11)

```java
public class Computer {
    private String model;
    private int ram;
    private int storage;

    public Computer(String model, int ram, int storage) {
        this.model = model;
        this.ram = ram;
        this.storage = storage;
    }

    public String getModel() { return model; }
    public void setModel(String model) { this.model = model; }
    public int getRam() { return ram; }
    public void setRam(int ram) { this.ram = ram; }
    public int getStorage() { return storage; }
    public void setStorage(int storage) { this.storage = storage; }

    public String run() { return "Компьютер работает"; }
    public String run(String program) { return "Запускает " + program; }
    public String run(int processes) { return "Запускает " + processes + " процессов"; }

    public String getPerformance() { return "Средняя"; }

    public String displayInfo() {
        return "Модель: " + model + ", ОЗУ: " + ram + " ГБ, накопитель: "
                + storage + " ГБ, производительность: " + getPerformance();
    }
}
```

```java
public class GamingPC extends Computer {
    private String videoCard;

    public GamingPC(String model, int ram, int storage, String videoCard) {
        super(model, ram, storage);
        this.videoCard = videoCard;
    }

    public String getVideoCard() { return videoCard; }
    public void setVideoCard(String videoCard) { this.videoCard = videoCard; }

    @Override
    public String getPerformance() { return "Высокая"; }

    // собственная перегрузка наследника
    public String run(String game, int fps) {
        return "Запускает игру " + game + " с " + fps + " FPS";
    }

    @Override
    public String displayInfo() {
        return super.displayInfo() + ", видеокарта: " + videoCard;
    }
}
```

```java
public class OfficePC extends Computer {
    private double monitorSize;

    public OfficePC(String model, int ram, int storage, double monitorSize) {
        super(model, ram, storage);
        this.monitorSize = monitorSize;
    }

    @Override
    public String getPerformance() { return "Средняя"; }

    public String run(String program, boolean minimized) {
        return "Запускает " + program + (minimized ? " в свёрнутом окне" : " в обычном окне");
    }

    @Override
    public String displayInfo() {
        return super.displayInfo() + ", монитор: " + monitorSize + " дюймов";
    }
}
```

### Демонстрация

```java
Computer computer = new Computer("Base", 8, 256);
System.out.println(computer.run());
System.out.println(computer.run("Word"));
System.out.println(computer.run(12));

Computer[] pcs = {
    new GamingPC("Aurora", 32, 2000, "RTX 4080"),
    new GamingPC("Titan", 16, 1000, "RX 7800"),
    new OfficePC("Office 1", 8, 256, 23.8),
    new OfficePC("Office 2", 16, 512, 27.0)
};

for (Computer pc : pcs) {
    System.out.println(pc.displayInfo());
    System.out.println(pc.getPerformance());
}

for (Computer pc : pcs) {
    if (pc instanceof GamingPC) {
        System.out.println(((GamingPC) pc).run("Cyberpunk", 120));
    } else if (pc instanceof OfficePC) {
        System.out.println(((OfficePC) pc).run("Excel", true));
    }
}
```

## Что спросят на защите

1. **Что такое полиморфизм?** Один интерфейс — разные реализации.
2. **Статический и динамический?** Перегрузка на компиляции, переопределение в runtime.
3. **Что такое перегрузка?** Одинаковое имя, разные параметры.
4. **Что такое переопределение?** Та же сигнатура в наследнике, новое поведение.
5. **Как отличить?** По параметрам и месту объявления.
6. **Какой тип использует `@Override`?** Динамический, переопределение.
7. **Можно ли перегрузить `static`?** Да, по параметрам.
8. **Можно ли переопределить `static`?** Нет, будет скрытие.
9. **Зачем `instanceof`?** Проверить фактический тип перед нисходящим приведением.

> [!tip] Фраза для ответа
> «Полиморфизм позволяет писать код против базового типа: `Computer[]`,
> `List<Readable>`, `Transport[]`. Добавление нового наследника не требует
> менять цикл обработки — это принцип открытости/закрытости».
