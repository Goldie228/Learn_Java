# Абстрактные классы (ЛР9)

> [!abstract] Одной фразой
> Абстрактный класс — это «полуфабрикат»: он задаёт общий контракт и может
> содержать готовую реализацию, но объект этого класса создать нельзя.

## Синтаксис

```java
public abstract class Transport {
    private double speed;

    public Transport(double speed) {
        this.speed = speed;
    }

    // абстрактный метод — без тела, с точкой с запятой
    public abstract String deliver();

    // конкретный метод — с реализацией
    public String info() {
        return "Скорость: " + speed;
    }
}
```

```java
public class Truck extends Transport {
    public Truck(double speed) { super(speed); }

    @Override
    public String deliver() { return "Доставляет груз по суше"; }
}
```

```java
Transport t = new Truck(80);   // можно: ссылка на абстрактный тип
// Transport t = new Transport(80); // ошибка компиляции
```

## Правила абстрактного класса

1. Объявляется с `abstract`.
2. Нельзя создать объект: `new AbstractClass()` — ошибка компиляции.
3. Может содержать **обычные поля**, конструкторы, конкретные методы.
4. Может не содержать ни одного абстрактного метода (но тогда его смысл — запрет
   создания объекта и роль вершины иерархии).
5. Не может быть `final` (его же надо наследовать).
6. Может реализовывать интерфейсы.
7. Ссылка абстрактного типа допустима и инициализируется объектом наследника.

## Правила абстрактного метода

1. Нет тела, заканчивается `;`.
2. Только в абстрактном классе или интерфейсе.
3. Не может быть `private` (наследник должен реализовать).
4. Не может быть `static` (статические методы не переопределяются).
5. Не может быть `final` (нельзя запретить переопределение).
6. Не может быть `native`, `synchronized`.

## Правила наследников

1. Конкретный наследник обязан реализовать **все** абстрактные методы.
2. Если реализовал не все — сам должен быть `abstract`.
3. Может переопределять конкретные методы.
4. Может добавлять свои поля и методы.
5. Конструктор наследника вызывает `super(...)`.

## Зачем конструктор абстрактному классу

Чтобы инициализировать общие поля при создании объекта наследника.
Цепочка вызовов: `Object` → конструктор абстрактного класса → конструктор
наследника.

```java
abstract class Animal {
    private String name;
    Animal(String name) {
        this.name = name;
        System.out.println("Конструктор Animal");
    }
    public String getName() { return name; }
    public abstract void makeSound();
}

class Dog extends Animal {
    Dog(String name) {
        super(name);
        System.out.println("Конструктор Dog");
    }
    @Override
    public void makeSound() { System.out.println("Гав-гав!"); }
}

new Dog("Шарик");
// Конструктор Animal
// Конструктор Dog
```

## Код варианта 9 (ЛР9)

```java
public abstract class Transport {
    private double capacity;
    private double speed;
    private double fuel;

    public Transport(double capacity, double speed, double fuel) {
        if (speed <= 0) {
            throw new IllegalArgumentException("Скорость должна быть больше нуля");
        }
        this.capacity = capacity;
        this.speed = speed;
        this.fuel = fuel;
    }

    public double getCapacity() { return capacity; }
    public void setCapacity(double capacity) { this.capacity = capacity; }
    public double getSpeed() { return speed; }
    public void setSpeed(double speed) {
        if (speed <= 0) throw new IllegalArgumentException("Скорость должна быть больше нуля");
        this.speed = speed;
    }
    public double getFuel() { return fuel; }
    public void setFuel(double fuel) { this.fuel = fuel; }

    public abstract String deliver();
    public abstract double calculateTime(double distance);

    protected void checkDistance(double distance) {
        if (distance < 0) throw new IllegalArgumentException("Расстояние не может быть отрицательным");
    }

    public String displayInfo() {
        return "Вместимость: " + capacity + " т, скорость: " + speed
                + " км/ч, топливо: " + fuel + " л";
    }
}
```

```java
public class Truck extends Transport {
    private double cargoWeight;

    public Truck(double capacity, double speed, double fuel, double cargoWeight) {
        super(capacity, speed, fuel);
        this.cargoWeight = cargoWeight;
    }

    public double getCargoWeight() { return cargoWeight; }
    public void setCargoWeight(double cargoWeight) { this.cargoWeight = cargoWeight; }

    @Override
    public String deliver() { return "Доставляет груз по суше"; }

    @Override
    public double calculateTime(double distance) {
        checkDistance(distance);
        return distance / getSpeed();
    }

    @Override
    public String displayInfo() {
        return super.displayInfo() + ", вес груза: " + cargoWeight + " т";
    }
}
```

```java
public class Ship extends Transport {
    private double tonnage;

    public Ship(double capacity, double speed, double fuel, double tonnage) {
        super(capacity, speed, fuel);
        this.tonnage = tonnage;
    }

    public double getTonnage() { return tonnage; }
    public void setTonnage(double tonnage) { this.tonnage = tonnage; }

    @Override
    public String deliver() { return "Доставляет груз по воде"; }

    @Override
    public double calculateTime(double distance) {
        checkDistance(distance);
        return distance / (getSpeed() * 0.8);   // коэффициент воды
    }

    @Override
    public String displayInfo() {
        return super.displayInfo() + ", тоннаж: " + tonnage + " т";
    }
}
```

### Полиморфный массив

```java
Transport[] fleet = {
    new Truck(20, 80, 300, 15),
    new Truck(10, 60, 150, 8),
    new Truck(25, 90, 400, 20),
    new Ship(500, 80, 1000, 300),
    new Ship(750, 40, 1500, 450)
};

double distance = 500;
for (Transport t : fleet) {
    System.out.println(t.displayInfo());
    System.out.println(t.deliver());
    System.out.printf("Время: %.2f ч%n", t.calculateTime(distance));
}
```

Ожидаемые значения для 500 км:

| Транспорт | Скорость | Формула | Время |
|-----------|----------|---------|-------|
| Truck | 80 | 500 / 80 | 6,25 ч |
| Truck | 60 | 500 / 60 | 8,33 ч |
| Truck | 90 | 500 / 90 | 5,56 ч |
| Ship | 80 | 500 / (80·0,8) | 7,81 ч |
| Ship | 40 | 500 / (40·0,8) | 15,63 ч |

## Абстрактный класс vs интерфейс

| Вопрос | Абстрактный класс | Интерфейс |
|--------|-------------------|-----------|
| Объект создать | нельзя | нельзя |
| Конструктор | есть | нет |
| Поля-состояние | да, любые | только `public static final` константы |
| Методы с реализацией | да | `default`, `static`, `private` |
| Наследование | один класс | сколько угодно интерфейсов |
| Когда выбирать | общая реализация + состояние | контракт поведения |

## Что спросят на защите

1. **Что такое абстрактный класс?** Класс с `abstract`, который нельзя инстанцировать; база для наследников.
2. **Можно ли создать объект?** Нет, только объект конкретного наследника.
3. **Что такое абстрактный метод?** Метод без тела, реализуется в наследнике.
4. **Может ли быть конструктор?** Да, вызывается через `super()`.
5. **Может ли не быть абстрактных методов?** Да, но тогда это просто запрет инстанцирования.
6. **Кто реализует все методы?** Первый конкретный наследник.
7. **`private`?** Нельзя.
8. **`static`?** Нельзя.
9. **`final`?** Нельзя.
10. **Наследник не реализовал метод?** Он сам должен быть `abstract`.
11. **Как вызвать конструктор?** `super(...)` первой строкой.

> [!tip] Фраза для ответа
> «Абстрактный класс — это частичная реализация и контракт. Я использую его,
> когда у наследников есть общее состояние и общий код, но ключевой метод
> должен быть разным. Если общего состояния нет — достаточно интерфейса».
