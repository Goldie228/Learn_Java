# Наследование (ЛР8)

> [!abstract] Одной фразой
> Наследование — механизм, при котором подкласс получает поля и методы
> суперкласса и может добавить свои или переопределить поведение.
> В Java — только **одиночное** наследование классов.

## Синтаксис

```java
class Parent {          // суперкласс
    // поля, методы
}

class Child extends Parent {   // подкласс
    // свои поля и методы
}
```

- Все классы неявно наследуют `Object`.
- Ключевое слово — `extends`.
- Множественное наследование классов **запрещено**.
- Конструкторы **не наследуются**.

## Что наследуется

| Член класса | Наследуется? | Доступ из подкласса |
|-------------|--------------|---------------------|
| `public` | да | напрямую |
| `protected` | да | напрямую |
| без модификатора (package-private) | да, если тот же пакет | только в своём пакете |
| `private` | формально да, но | **доступа нет**, только через геттеры/сеттеры |
| конструктор | нет | вызывается через `super(...)` |
| `static` | да (но это не полиморфизм) | по имени класса |

> [!important] Частый вопрос
> «Наследуются ли приватные поля?» — Поля существуют в объекте подкласса,
> но **прямого доступа** к ним нет. Работать с ними можно только через
> унаследованные `public`/`protected` методы.

## `super` и `this`

```java
class Point1D {
    private int x;
    public Point1D(int x) { this.x = x; }
    public int getX() { return x; }
}

class Point2D extends Point1D {
    private int y;
    public Point2D(int x, int y) {
        super(x);       // обязательно первой строкой
        this.y = y;
    }
    public int getY() { return y; }
}

class Point3D extends Point2D {
    private int z;
    public Point3D(int x, int y, int z) {
        super(x, y);
        this.z = z;
    }
    public Point3D() {
        this(-1, -1, -1);   // вызов другого конструктора этого же класса
    }
    public int getZ() { return z; }
}
```

Правила:

1. `super(...)` или `this(...)` — **только первая строка** конструктора.
2. Нельзя одновременно `super(...)` и `this(...)`.
3. `super.method()` вызывает версию суперкласса (не свою переопределённую).
4. `super.field` — доступ к полю суперкласса (если оно видимо).
5. «Перескочить» через суперкласс к его родителю нельзя.

### Порядок вызовов конструкторов

```java
class Animal {
    Animal() { System.out.println("Animal"); }
}
class Dog extends Animal {
    Dog() { System.out.println("Dog"); }
}
new Dog();
// Animal
// Dog
```

Сначала полностью инициализируется суперкласс, затем поля подкласса,
затем тело конструктора подкласса.

> [!warning] Плохая практика
> Не вызывай в конструкторе методы, которые можно переопределить: подкласс
> ещё не инициализирован, а его версия метода уже может выполниться.

## Переопределение (`@Override`)

```java
class Animal {
    public String sound() { return "какой-то звук"; }
}

class Dog extends Animal {
    @Override
    public String sound() { return "Гав-гав!"; }
}
```

Правила:

- имя и параметры совпадают;
- возвращаемый тип совпадает или является подтипом (ковариантный возврат);
- доступ нельзя сужать (`public` → `protected` нельзя);
- нельзя переопределить `private`, `final`, `static`;
- `static`-метод можно **скрыть**, но это не переопределение;
- `@Override` — не обязательна, но страхует от опечаток.

## `instanceof` и приведение типов

```java
Animal a = new Dog();

if (a instanceof Dog) {
    Dog d = (Dog) a;      // безопасное нисходящее приведение
    System.out.println(d.sound());
}

// Java 16+: pattern matching
if (a instanceof Dog d) {
    System.out.println(d.sound());
}
```

- Восходящее (`Dog → Animal`) — неявное и безопасное.
- Нисходящее (`Animal → Dog`) — явное; без проверки возможен `ClassCastException`.
- На экзамене чаще ждут классический вариант с проверкой и приведением.

## Код варианта 9 (ЛР8)

```java
public class Computer {
    private String processor;
    private int ram;
    private int storage;

    public Computer(String processor, int ram, int storage) {
        this.processor = processor;
        this.ram = ram;
        this.storage = storage;
    }

    public String getProcessor() { return processor; }
    public void setProcessor(String processor) { this.processor = processor; }
    public int getRam() { return ram; }
    public void setRam(int ram) { this.ram = ram; }
    public int getStorage() { return storage; }
    public void setStorage(int storage) { this.storage = storage; }

    public String getPerformance() { return "Базовая производительность"; }

    public String displayInfo() {
        return "Процессор: " + processor + ", ОЗУ: " + ram
                + " ГБ, накопитель: " + storage + " ГБ";
    }
}
```

```java
public class GamingPC extends Computer {
    private String videoCard;

    public GamingPC(String processor, int ram, int storage, String videoCard) {
        super(processor, ram, storage);
        this.videoCard = videoCard;
    }

    public String getVideoCard() { return videoCard; }
    public void setVideoCard(String videoCard) { this.videoCard = videoCard; }

    @Override
    public String getPerformance() { return "Высокая производительность"; }

    @Override
    public String displayInfo() {
        return super.displayInfo() + ", видеокарта: " + videoCard;
    }

    public String playGame() { return "Запускает современную игру"; }
}
```

```java
public class OfficePC extends Computer {
    private double monitorSize;

    public OfficePC(String processor, int ram, int storage, double monitorSize) {
        super(processor, ram, storage);
        this.monitorSize = monitorSize;
    }

    public double getMonitorSize() { return monitorSize; }
    public void setMonitorSize(double monitorSize) { this.monitorSize = monitorSize; }

    @Override
    public String getPerformance() { return "Средняя производительность"; }

    @Override
    public String displayInfo() {
        return super.displayInfo() + ", монитор: " + monitorSize + " дюймов";
    }

    public String printDocument() { return "Печатает документ"; }

```

### Массив базового типа — обязательный элемент задания

```java
public class Main {
    public static void main(String[] args) {
        Computer[] computers = new Computer[5];   // 3 + 2
        computers[0] = new GamingPC("Intel i9", 32, 2000, "RTX 4080");
        computers[1] = new GamingPC("Ryzen 7", 16, 1000, "RTX 3070");
        computers[2] = new GamingPC("Intel i7", 16, 512, "RX 6700");
        computers[3] = new OfficePC("Intel i5", 8, 256, 21.5);
        computers[4] = new OfficePC("Ryzen 5", 16, 512, 27.0);

        for (Computer c : computers) {
            System.out.println(c.displayInfo());
            System.out.println(c.getPerformance());   // динамический полиморфизм
        }

        for (Computer c : computers) {
            if (c instanceof GamingPC) {
                GamingPC g = (GamingPC) c;
                System.out.println(g.playGame());
            } else if (c instanceof OfficePC) {
                OfficePC o = (OfficePC) c;
                System.out.println(o.printDocument());
            }
        }
    }
}
```

## Что спросят на защите

1. **Что такое наследование?** Передача полей и методов от суперкласса подклассу.
2. **Какие ключевые слова?** `extends`, `super`, `this`, `@Override`, `instanceof`.
3. **Что не наследуется?** Конструкторы; приватные члены недоступны напрямую.
4. **Зачем `super()`?** Вызвать конструктор суперкласса; только первой строкой.
5. **Можно ли переопределить `private`/`static`/`final`?** Нет.
6. **Чем отличается переопределение от перегрузки?** См. [[04 Полиморфизм]].
7. **Порядок конструкторов?** `Object` → суперкласс → подкласс.
8. **Что будет при `(Dog) animal`, если там `Cat`?** `ClassCastException`.

> [!tip] Фраза для ответа
> «Наследование реализует отношение is-a. Подкласс получает реализацию
> суперкласса, может добавить поля и переопределить методы. Повторное
> использование кода — плюс, жёсткая связь — минус, поэтому глубокая
> иерархия не всегда хороша».
