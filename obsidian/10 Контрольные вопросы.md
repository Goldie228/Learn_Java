# Контрольные вопросы — быстрые ответы

> [!tip] Как отвечать
> 1–2 предложения по сути, потом маленький пример. Не уходи в детали, пока
> не спросят. Если вопрос про «чем отличается» — отвечай таблицей/двумя
> пунктами.

## ЛР8. Наследование

1. **Что такое наследование?**
   Механизм, при котором подкласс получает поля и методы суперкласса
   и может добавить свои или переопределить поведение. В Java — одиночное.

2. **Какие ключевые слова используются?**
   `extends` — наследование, `super` — доступ к суперклассу, `this` — к текущему
   объекту, `@Override` — переопределение, `instanceof` — проверка типа.

3. **Какие члены класса не наследуются?**
   Конструкторы. Приватные члены формально есть в объекте, но недоступны
   напрямую; package-private недоступны из другого пакета.

## ЛР9. Абстрактные классы

1. **Что такое абстрактный класс?**
   Класс с `abstract`, который нельзя инстанцировать; база для наследников.

2. **Можно ли создать объект?**
   Нет: `new AbstractClass()` — ошибка компиляции. Можно ссылку на абстрактный
   тип, указывающую на наследника.

3. **Что такое абстрактный метод?**
   Метод без тела, объявленный с `abstract` и заканчивающийся `;`.

4. **Может ли быть конструктор?**
   Да, для инициализации полей; вызывается из наследника через `super()`.

5. **Может ли не быть абстрактных методов?**
   Да, но тогда класс всё равно нельзя создать; он служит вершиной иерархии.

6. **Кто реализует все абстрактные методы?**
   Первый конкретный (неабстрактный) класс-наследник.

7. **Можно ли `private`?**
   Нет, наследник не сможет переопределить.

8. **Можно ли `static`?**
   Нет, статические методы не переопределяются.

9. **Можно ли `final`?**
   Нет, `final` запрещает наследование, а смысл абстрактного класса — наследование.

10. **Что если наследник не реализовал метод?**
    Компилятор потребует объявить наследника `abstract`.

11. **Как вызвать конструктор абстрактного класса?**
    `super(...)` первой строкой конструктора наследника.

## ЛР10. Интерфейсы

1. **Что такое интерфейс?**
   Контракт поведения: набор методов, которые класс обязуется реализовать.

2. **Можно ли создать объект?**
   Нет, у интерфейса нет конструктора.

3. **Какие методы могут быть?**
   Абстрактные, `default`, `static`, `private` (Java 9+).

4. **Какие поля?**
   Только `public static final` — константы.

5. **Чем отличается от абстрактного класса?**
   Нет конструктора и состояния; только константы; можно реализовать несколько
   интерфейсов; методы с телом — `default`/`static`.

6. **Как класс реализует интерфейс?**
   `implements`, все методы `public`; если не все — класс `abstract`.

7. **Может ли класс реализовать несколько интерфейсов?**
   Да, через запятую.

8. **Может ли интерфейс наследовать интерфейс?**
   Да, и даже несколько (`interface C extends A, B`).

9. **Что такое `default`-метод?**
   Метод интерфейса с реализацией; класс может не переопределять.

## ЛР11. Полиморфизм

1. **Что такое полиморфизм?**
   Один интерфейс — разные реализации; вызов метода зависит от фактического типа.

2. **Статический и динамический?**
   Перегрузка решается компилятором; переопределение — во время выполнения.

3. **Что такое перегрузка?**
   Одинаковое имя, разные параметры (количество, тип, порядок).

4. **Что такое переопределение?**
   В наследнике метод с той же сигнатурой и новым поведением.

5. **Как отличить?**
   Перегрузка — разные параметры; переопределение — те же, но другой класс.

6. **Какой тип использует `@Override`?**
   Динамический, переопределение.

7. **Можно ли перегрузить `static`?**
   Да, по параметрам.

8. **Можно ли переопределить `static`?**
   Нет, будет скрытие метода, а не переопределение.

9. **Зачем `instanceof`?**
   Проверить фактический тип перед нисходящим приведением, избежать `ClassCastException`.

## ЛР12. Generics и коллекции

1. **Основные интерфейсы коллекций?**
   `Collection`, `List`, `Set`, `Queue`, `Map` (Map — отдельно).

2. **`List` vs `Set`?**
   List упорядочен и допускает дубликаты; Set — уникальные элементы.

3. **`ArrayList` vs `LinkedList`?**
   ArrayList — массив, быстрый доступ по индексу; LinkedList — узлы, быстрее
   вставка/удаление в середине.

4. **`HashSet` vs `TreeSet`?**
   HashSet — хеш-таблица без порядка; TreeSet — отсортированное дерево.

5. **`HashMap` vs `TreeMap`?**
   HashMap — без порядка; TreeMap — ключи отсортированы.

6. **Как перебрать?**
   for-each, `Iterator`, `forEach`, `entrySet()`/`keySet()`/`values()`.

7. **Что такое `Iterator`?**
   Курсор с `hasNext()`, `next()`, `remove()` для последовательного обхода.

8. **Как отсортировать?**
   `Collections.sort` / `list.sort` с `Comparable` или `Comparator`.

## ЛР13. Исключения

1. **Что такое исключение?**
   Объект с информацией об ошибке времени выполнения.

2. **Иерархия?**
   `Throwable` → `Error` и `Exception`; `Exception` → `RuntimeException` и checked.

3. **Checked vs unchecked?**
   Checked проверяет компилятор (надо `catch`/`throws`); unchecked — наследники
   `RuntimeException`, проверка не требуется.

4. **Ключевые слова?**
   `try`, `catch`, `finally`, `throw`, `throws`.

5. **`try-catch-finally`?**
   Попытка → обработка → блок, который выполняется всегда.

6. **`throw` vs `throws`?**
   `throw` бросает объект; `throws` объявляет типы в сигнатуре метода.

7. **Когда выполняется `finally`?**
   Всегда, кроме `System.exit()` и падения JVM.

8. **Как создать своё исключение?**
   Наследовать `Exception` (checked) или `RuntimeException` (unchecked),
   вызвать `super(message)`, добавить поля.

9. **`try-with-resources`?**
   Автоматическое закрытие ресурсов, реализующих `AutoCloseable`.

10. **Как обработать несколько типов?**
    Несколько `catch` или multi-catch `catch (A | B e)`.

11. **Multi-catch?**
    Один блок для нескольких несвязанных типов; переменная неявно `final`.

12. **Деление на ноль?**
    `ArithmeticException` (для целых).

13. **Что если не обработать?**
    Исключение поднимается по стеку; без обработчика программа завершается.

14. **Как получить сообщение?**
    `e.getMessage()`; полный стек — `e.printStackTrace()`.

15. **Что такое stack trace?**
    Список вызовов от точки ошибки до `main`.

16. **Несколько ресурсов в try-with-resources?**
    Перечислить через `;`; закроются в обратном порядке.

## ЛР14. Файловый ввод-вывод

1. **Что такое поток?**
   Абстракция источника или приёмника данных; скрывает детали устройства.

2. **Родители байтовых и символьных потоков?**
   `InputStream`/`OutputStream` и `Reader`/`Writer`.

3. **Основные методы `InputStream`?**
   `read()`, `read(byte[])`, `skip()`, `available()`, `close()`, `mark/reset`
   (если поддерживаются).

4. **Основные методы `OutputStream`?**
   `write(int)`, `write(byte[])`, `write(byte[], int, int)`, `flush()`, `close()`.

5. **Зачем `File`?**
   Представляет путь и метаданные файла/каталога, но не содержимое.

6. **`FileInputStream` vs `FileOutputStream`?**
   Чтение байтов vs запись байтов; вывод по умолчанию перезаписывает файл.

7. **Зачем буферизованные потоки?**
   Буфер уменьшает число обращений к диску и ускоряет ввод-вывод.

8. **Преимущества `Path`/`Files`?**
   Больше операций, кодировки, NIO, удобная обработка ошибок и ссылок.

9. **Почему классов так много?**
   Разные источники (файл, память, сеть), способы доступа (байты/символы,
   буфер, построчно) и кодировки.

10. **Почему обязателен try-catch?**
    `IOException` — checked; плюс ресурсы нужно закрывать, лучше через
    try-with-resources.

## ЛР15. Git

1. **Что такое VCS?**
   Система, хранящая историю изменений и позволяющая откатываться к версиям.

2. **Чем Git отличается от SVN/Perforce?**
   Распределённый: полная история у каждого, локальные операции, снимки,
   SHA-1.

3. **Три состояния файла?**
   Modified, staged, committed.

4. **Основные команды?**
   `init`, `clone`, `status`, `add`, `commit`, `log`, `diff`, `branch`,
   `switch/checkout`, `merge`, `push`, `pull`.

5. **Что такое ветка?**
   Независимая линия разработки; подвижная ссылка на коммит.

6. **Конфликт слияния и как разрешить?**
   Обе ветки изменили один участок. Убрать маркеры, оставить нужный код,
   `git add`, `git commit`.

7. **Git vs GitHub?**
   Git — VCS; GitHub — платформа для удалённых репозиториев, PR и ревью.

8. **Pull Request?**
   Предложение влить ветку в основную; обсуждение и код-ревью до merge.

9. **`.gitignore`?**
   Список файлов/каталогов, которые Git не отслеживает (сборка, IDE, логи,
   секреты).
